# Error codes

Every error is `application/problem+json` with `code`, `status`, `detail`, `retryable` and `requestId`. The `code` is stable (codes are added, never renamed); `detail` is for people. `retryable` answers one question: is it safe to send exactly this request again? A write whose outcome is unknown is never retryable: check the order book first.

Rate-limit refusals (429) also say whose limit was hit: `scope` (`client`, `upstream`, `queue`, `consumer-cap`), `retryAfterMs` and `limit`. Read those fields, not `detail`. See [rate-limits.md](../guides/rate-limits.md).

Generated from `server/bridge/core/errors.mjs` and `server/bridge/core/errorCatalogue.mjs`. The running Bridge serves the same list at `GET /v1/errors`, and the dashboard shows it under Developers.

| Code | HTTP | Retry | What it means | What to do |
|---|---|---|---|---|
| `INVALID_JSON` | 400 | no | The body could not be read as JSON (a trailing comma, single quotes, or a body that was cut off). | Send valid JSON with the header `Content-Type: application/json`. Check the body with a JSON validator before sending. |
| `VALIDATION_FAILED` | 400 | no | The request reached the Bridge but a field is missing, has the wrong type or is out of range. The `errors` list names each field, with a `code` for programs (`required`, `invalid_enum` with the `allowed` values, `too_small`, `too_big`, `invalid_format`, `unknown_field` ...). | Read `errors[].path`, `errors[].code` and `errors[].message` (for `invalid_enum`, `errors[].allowed` lists what is accepted), correct those fields and send it again. Retrying the same body will fail the same way. |
| `UNAUTHENTICATED` | 401 | no | No API key was sent, the key is wrong, it has expired or it was revoked. | Send `Authorization: Bearer mcb_<id>_<secret>`. Check the key under Developers > Apps (status and expiry). If it is lost, revoke it and create a new one: a key is shown only once. |
| `ACCOUNT_FORBIDDEN` | 403 | no | The key is limited to some broker accounts and this request names another one. | Send the `account` the key may use, or create a key that includes this account. |
| `CANNOT_TRADE` | 403 | no | The account is not ready to trade right now (for example a missing static IP registration or a closed session). | Open dashboard > Safety > Trading readiness for the exact reason and what to do. |
| `DAILY_LIMIT_REACHED` | 403 | no | A daily safety limit (orders, loss or value) has been reached. | Nothing to retry today unless you raise the limit on the computer running the Bridge. The limits and what counted are under Safety. |
| `HOST_NOT_ALLOWED` | 403 | no | The request was addressed to a host name the Bridge does not accept. This guards against web pages that point a look-alike name at your computer. | Call the Bridge as http://127.0.0.1:<port> or http://localhost:<port>. For a tunnel or proxy, add its host name to the allowed hosts in the configuration. |
| `LOOPBACK_ONLY` | 403 | no | This action (keys, admin settings, anything that could move money or open the Bridge to others) works only from the computer the Bridge runs on. | Run it on that computer: the dashboard, the `mc-bridge` command, or curl to 127.0.0.1. It cannot be done through a tunnel or from another machine. |
| `MARKET_CLOSED` | 403 | no | The exchange is closed for this instrument, so an order would not be accepted. | Send it when the market is open. GET /v1/calendar/status says whether it is open and when it next opens. |
| `ORDER_GATE_CLOSED` | 403 | no | A rule that guards live orders said no, so the order was not sent. | Read `detail` for which rule it was. The live-order conditions are listed in the dashboard under Safety. |
| `ORIGIN_NOT_ALLOWED` | 403 | no | A browser page from another site tried to call the Bridge. The Bridge only answers its own dashboard and origins you listed. | Call from a server or script instead of a web page. If you run your own page, add its origin to the allowed origins in the configuration. |
| `PAPER_ONLY` | 403 | no | This account is paper only: live trading is not switched on for it. | Send `mode: "paper"`. Live orders need several opt-ins made on the computer running the Bridge: see the safety guide. |
| `SCOPE_REQUIRED` | 403 | no | The key is valid, but its scope does not allow this action (for example a read key sending an order). | Use a key with the scope this route needs: Developers > Scope finder tells you which. Create a new app with that preset rather than widening a key you already shared. |
| `ACCOUNT_NOT_FOUND` | 404 | no | No broker account has this id. | List accounts with GET /v1/accounts and use one of the ids it returns. |
| `NOT_FOUND` | 404 | no | There is no such route or item. On a route this is usually a typo, or the route belongs to a newer Bridge than the one you run. | Check the path against GET /v1/meta (the list of routes this Bridge serves) or the OpenAPI file. Update the Bridge if a documented route is missing. |
| `ORDER_NOT_FOUND` | 404 | no | No order has this id (or it belongs to an account this key cannot see). | List orders with GET /v1/orders and copy the id. To find an order you sent with your own id, use GET /v1/orders/by-client-id/{clientOrderId}. |
| `SYMBOL_NOT_FOUND` | 404 | no | The symbol could not be matched to an instrument. | Use the canonical form EXCHANGE:SYMBOL (for example NSE:RELIANCE). Search with GET /v1/instruments/search, or convert with POST /v1/symbols/resolve. |
| `METHOD_NOT_ALLOWED` | 405 | no | The route exists but not for this HTTP method (for example GET on a route that only accepts POST). | Use the method the documentation shows for this path. The `Allow` header lists the methods it accepts. |
| `AMBIGUOUS_SYMBOL` | 409 | no | The text matches more than one instrument, so the Bridge will not guess. | Pick one of the candidates in the answer and send its full canonical symbol. |
| `DUPLICATE_CLIENT_ORDER_ID` | 409 | no | Your own `clientOrderId` was already used for an order on this account. | Look the earlier order up with GET /v1/orders/by-client-id/{clientOrderId}. For a new order, use a new id. |
| `IDEMPOTENCY_IN_PROGRESS` | 409 | yes | A request with this `Idempotency-Key` is still being processed. | Wait a moment and send the same request with the same key again. You will get the original result, not a second action. |
| `IDEMPOTENCY_KEY_REUSED` | 409 | no | You sent an `Idempotency-Key` that was already used with a different request body. The Bridge refuses it so a retry can never become a second, different order. | Use a new key for a new order. Reuse a key only when you resend exactly the same request. |
| `STATE_CONFLICT` | 409 | yes | The item changed, or is busy, while you were working on it (for example an order that was filled before your change arrived). | Read it again, then decide. Retrying after a short wait is safe. |
| `PAYLOAD_TOO_LARGE` | 413 | no | The request body is bigger than the route allows. | Send less per request (split a long symbol list or a big batch into several calls). |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | no | The body was not sent as JSON. | Add the header `Content-Type: application/json` and send a JSON body. |
| `CAPABILITY_UNSUPPORTED` | 422 | no | This broker cannot do what you asked (for example an order type or a data kind it does not offer). | Check the broker's abilities in the dashboard under Accounts, or use another account or order type. |
| `CONFIRMATION_REQUIRED` | 422 | no | This order is waiting for a person to approve it on the computer running the Bridge. Approval never happens through the API. | Open the dashboard > Orders and approve or reject the ticket. Your program can poll GET /v1/tickets. |
| `INVALID_ORDER` | 422 | no | The order failed a check before it was sent (for example a bad lot size, a price outside the allowed range, or too little margin). Nothing was sent to the broker. | Read `detail`, correct the order and send it again. POST /v1/orders/preview checks an order without placing it. |
| `SESSION_EXPIRED` | 422 | no | The login with the broker has ended, so the Bridge cannot read or place anything for that account. | Log in again: dashboard > Accounts > Log in, or `mc-bridge accounts connect <accountId>`. Most brokers need a fresh login every day. |
| `KILL_SWITCH_ACTIVE` | 423 | no | The kill switch is on. No orders are sent until it is released. | Release it on the computer running the Bridge (dashboard > Safety, or `mc-bridge kill release`). It cannot be released through a tunnel. |
| `ORDER_RATE_LIMITED` | 429 | yes | The account reached its order-rate cap. The cap protects you from a runaway program and the broker from too many orders. | Wait `retryAfterMs`, then retry. Slow the program down: do not loop on orders. |
| `RATE_LIMITED` | 429 | yes | This key sent too many requests: its own rate, daily cap or number of requests waiting. Other keys are not affected. | Wait `retryAfterMs` (the `Retry-After` header has the same wait in seconds), then retry. Send fewer requests, batch symbols into one call, or raise this key's quota under Sources > Quotas (on this computer). |
| `SUBSCRIPTION_LIMIT` | 429 | no | The broker's live feed allows only so many symbols at once and the limit is reached. | Unsubscribe from symbols you no longer need, or use fewer symbols. Waiting alone will not clear it. |
| `UPSTREAM_RATE_LIMITED` | 429 | yes | The broker's shared request budget is used up, or the shared queue is full. This is not about your key: every tool on this Bridge shares that budget. | Wait `retryAfterMs` and retry. `scope` says why (`upstream` or `queue`). Ask for fewer or larger batches, and read the budget with GET /v1/limits. |
| `INTERNAL` | 500 | no | Something went wrong inside the Bridge. The message is hidden on purpose: it could contain private details. | Quote the `requestId` when you report it. The Bridge log on the computer has the cause. Retrying the same request is not guaranteed to help. |
| `NOT_IMPLEMENTED` | 501 | no | This part of the Bridge is not built in this version. | Update the Bridge, or use another route. Check the changelog for when it arrives. |
| `UPSTREAM_ERROR` | 502 | no | The broker returned an error. `broker.code` and `broker.message` carry the broker's own words. | Read `broker.message`. For a read, retry later. For an order, check the order book before sending it again. |
| `BROKER_UNAVAILABLE` | 503 | yes | The Bridge could not reach the broker (their servers are down or the connection failed). | Retry after a short wait, with backoff. Check your internet connection and the broker's status page. |
| `POSITION_UNKNOWN` | 503 | yes | The Bridge could not read your current position, so it did not place the order. A guess could have doubled a position. | Wait a few seconds and send the same request again, or check GET /v1/positions first. |
| `OUTCOME_UNKNOWN` | 504 | no | An order was sent but the broker did not confirm whether it went through. It may or may not exist. | Do not send it again. Check GET /v1/orders (or by client order id) and the broker's own order book first, then decide. |
| `UPSTREAM_TIMEOUT` | 504 | yes | The broker did not answer in time. For a read nothing is lost. | Retry after a short wait. If it happens often, ask for less data per call. |
