|---|---|---|---|

## 5. Every number: formula, format and edge cases

Notation:
- Per strike `k` and side `s ∈ {ce, pe}`: `OI` = OI now, `OIr` = OI at the window reference, `ΔOI = OI − OIr`.
- `LTP`, `LTPr` and `ΔLTP` follow the same pattern. `V` = volume in the window.
- "Prev close" window: `ΔOI = leg.oiChange`, `OIr = OI − ΔOI`, `ΔLTP = leg.change`, `V = leg.volume`.
- Snapshot window: values come from the reference snapshot. A strike missing from the reference has `OIr = 0` and `LTPr = null`: it is new, not excluded.
- Units: Lots = qty ÷ `chain.lotSize`, using each chain's own lot size; Qty = raw.
  - The unit is shown in the ladder header ("OI (lots)") and in tile titles.
  - Default unit is Lots.
- Format:
  - OI and ΔOI use `formatCompact` (signed for Δ); ratios use `formatFixed(v, 2)`; % uses `formatPercent`; strikes use `formatInt`. No grouping commas.
  - Missing values print `--`.
- **Band** = ATM ±N strikes (N ∈ 10, 20, 30, All; default 10), over the fetched rows.
- **Chain** = all fetched rows (coverage shown).

### 5.1 Tiles (patched in place, never rebuilt)
| Tile | Value | Sub-line | Title (one line) |
|---|---|---|---|
| Spot (desktop and tablet only) | `formatFixed(spot, 2)` | `ATM {atm} · {DTE label}` | "Underlying LTP and the strike closest to it" |
| PCR OI | chain PCR_OI | `±N {band PCR_OI} · Vol {PCR_Vol}` (phone: `Vol {PCR_Vol}`) + band word (§5.2) + trend arrow vs the window reference when one exists | "Put OI ÷ call OI. Writer view: high = put writing below (support), low = call writing above (cap). Context, not a signal." |
| PCR ΔOI | ratio, or "n/a" (§5.2) | when it is a ratio: `PE {+x} · CE {+y}`; otherwise the kind text | "Put ΔOI ÷ call ΔOI over the window and the band" |
| PCR Vol (desktop only) | band PCR_Vol | `window {label}` | "Put volume ÷ call volume in the window. Noisy on expiry day." |
| Max pain | strike | `{±pts} ({±%}) from spot · {relevance}` | "Settlement where option buyers collect the least, over {n} strikes {lo}–{hi}. Matters mainly in the last 1–2 sessions. Not a forecast." When `edge` is set, add " · at range edge" and the `warn` class. |
| Resistance | R1 strike | `{OI lots} · {+dist pts} · {σ}σ · {fresh tag}` | "Call strike at or above spot with the most OI" |
| Support | S1 strike | same, with negative distance | "Put strike at or below spot with the most OI" |
| Window | label, e.g. "15m" or "Prev close" | `since 10:42 · {n} snaps` or `vs previous close` | coverage explanation (§7.3) |

Rules:
- Tile values are never green or red.
- The trend arrow is ▲ or ▼ in the foreground colour, with text in the title, e.g. "PCR 0.94 at 10:30".
- `warn` uses `--ios-orange-ink`.

### 5.2 PCR (`O.pcrSet(rows, side-picks) → { oi, vol, chg }`)
- `PCR_OI = ΣPE OI ÷ ΣCE OI`. It is null when ΣCE OI = 0.
- `PCR_Vol = ΣPE V ÷ ΣCE V`. It is null when ΣCE V = 0.
- `PCR_ΔOI`: let `p = ΣPE ΔOI` and `c = ΣCE ΔOI` (ΔOI null on a leg counts as 0; if every leg's ΔOI is null, the whole result is null).

| Condition | `chg.ratio` | `chg.kind` | Text |
|---|---|---|---|
| p > 0 and c > 0 | p ÷ c | `ratio` | (the ratio) |
| p > 0, c ≤ 0 | null | `put-add-call-cut` | "Puts added, calls cut: supportive" |
| p ≤ 0, c > 0 | null | `call-add-put-cut` | "Calls added, puts cut: capping" |
| p < 0, c < 0 | null | `both-cut` | "Both sides unwinding" |
| p = 0 and c = 0 | null | `flat` | "No change" |

Every result also carries `p` and `c`, so the sub-line can print them.

- **Band words** (writer view, labelled "writer view" in the How-to-read sheet): ≥ 1.5 "very put-heavy (extreme)", ≥ 1.2 "put-heavy", > 0.8 "balanced", > 0.6 "call-heavy", ≤ 0.6 "very call-heavy (extreme)".
  - Thresholds live in one exported constant, `PCR_BANDS`. Per-index baselines come LATER.
- Expiry day (DTE < 1 session): PCR Vol gets the suffix "· expiry-day noise".

### 5.3 Max pain (`O.maxPainCurve(rows) → { strike, curve:[{strike, pain}], n, lo, hi, edge }`)
- For each listed strike K: `pain(K) = Σ_k CE_OI_k · max(0, K − k) + Σ_k PE_OI_k · max(0, k − K)`.
- `strike` is the argmin. On a tie, take the strike closest to spot, and if still tied, the lower one.
- `edge` is true when the argmin is the first or last fetched strike.
- `n`, `lo` and `hi` describe coverage. The result is null with fewer than 3 strikes with OI.
- `O.maxPain(rows)` keeps returning `maxPainCurve(rows)?.strike ?? null`. The existing tests must still pass.
- **Relevance** (`O.maxPainRelevance(expiry, now)`): "high" when ≤ 2 trading sessions are left (counting weekdays), "medium" when ≤ 5, else "low".
- The curve is LATER as a small SVG. This round shows only the number, distance and relevance.

### 5.4 Walls (`O.oiWalls(rows, side, spot, { top = 3, band }) → [{ rank, strike, oi, share, strength, d, fresh, dist, distPct }]`)
- Candidates:
  - Calls: strikes ≥ spot.
  - Puts: strikes ≤ spot.
  - If spot is null, use all strikes.
- Ranking is by OI, descending. On a tie, the strike nearer to spot ranks higher.
- `share = OI ÷ Σ side OI (chain)`.
- `strength = OI ÷ mean side OI over band rows with OI > 0`. When it is ≥ 2, show the tag "strong".
- `d` = ΔOI at that strike for the current window.
- `fresh`: `"fresh"` if `d ≥ 0.05·OIr` and `d > 0`; `"unwinding"` if `d ≤ −0.05·OIr`; `"steady"` otherwise; null if `d` is null. Treat `OIr = 0` with `d > 0` as fresh.
- `dist = strike − spot` (signed). `distPct = dist ÷ spot × 100`. The σ multiple is `|dist| ÷ move` (move from `context()`); null without IV.
- **Fresh wall**: also export `O.freshWall(rows, side)`, the strike with the largest positive ΔOI on that side (any strike). It is shown under the walls table as "Most added: 26500 CE +1.2L".
- **Wall shift** (needs snapshots): compare R1/S1 now with R1/S1 computed on the reference snapshot. Show "↑ from 26400" or "↓ from 25900"; nothing when unchanged.
- Walls block: two mini tables, Calls (R1–R3) and Puts (S1–S3), with columns Strike, OI, Δ, Share, Dist (pts and σ), Tag.

### 5.5 Build-up classification (`O.classifyBuildup({ d, oiRef, dLtp, ltpRef, v }, { lot, minLots = 10, minOiPct = 1, minPxPct = 0.5, tick = 0.05, churnX = 5 })`)
1. If `d` or `dLtp` is null, return null.
2. `oiSig = |d| ≥ max(minOiPct% · oiRef, minLots · lot)`.
3. `pxSig = |dLtp| ≥ max(minPxPct% · ltpRef, 2 · tick)`. When `ltpRef` is null, use `2 · tick`.
4. If not `oiSig`: return `"CH"` (churn) when `v ≥ churnX · minLots · lot`; otherwise return null (flat).
5. If not `pxSig`: return `"CH"` when `v ≥ churnX · |d|`; otherwise return null.
6. Otherwise: `d > 0`: `dLtp > 0 ? "LB" : "SB"`; `d < 0`: `dLtp > 0 ? "SC" : "LU"`.

`BUILDUP_NAMES` gains `CH: "Churn"`. `O.buildup(leg)` (chain column) stays unchanged.

### 5.6 Build-up summary and direction (`O.buildupSummary(rows, opts) → { ce, pe, score, tone, text }`)
- Over **band** rows, for each side and class (LB, SB, SC, LU, CH): `n` = count and `lots = Σ|d| ÷ lot`.
- Direction map (exported `BUILDUP_DIR`):

| Class | CE | PE |
|---|---|---|
| LB (long build-up) | +1 (call buying, bullish) | −1 (put buying, bearish) |
| SB (short build-up, writing) | −1 (call writing, capping) | +1 (put writing, supportive) |
| SC (short covering) | +1 (call writers exit, bullish) | −1 (put writers exit, bearish) |
| LU (long unwinding) | −1 (call longs exit) | +1 (put longs exit) |

- `score = Σ dir · |d| ÷ Σ|d|` over the four directional classes, both sides. It runs from −1 to +1 and is null when the denominator is 0.
- `tone` and `text`, applied in order:
  1. If SB is ≥ 50% of the directional |d| on **both** sides: `range`, "Writers on both sides: range {S1}–{R1}".
  2. score ≥ 0.25: `up`, "Bullish tilt".
  3. score ≤ −0.25: `down`, "Bearish tilt".
  4. Otherwise: `mixed`, "Mixed".
- **UI**: a 2×5 matrix. Rows are Calls and Puts. Columns are LB, SB, SC, LU and Churn. Each cell shows `n` and the lots.
  - The dominant directional cell per side is bold.
  - Each column header has a title giving the definition **and** the direction for that side, e.g. "SB on calls = call writing: caps the upside".
  - Under the matrix: "Calls: SB dominant → capping · Puts: SB dominant → supportive", then `text`.
  - No green or red. The tone shows as a word and a ▲/▼/↔ glyph.

### 5.7 Movers (`O.oiMovers(rows, { n = 5 }) → { adds, unwinds }`)
- Over **chain** rows, both sides: `adds` are the top n by `d > 0`; `unwinds` are the top n by `d < 0` (most negative first).
- Each item: `{ strike, side, d, dPct (d ÷ OIr × 100, null when OIr = 0 → print "new"), oi, dLtp, cls (classifyBuildup), dir, v }`.
- A row is tagged "at wall" when its strike is R1–R3 or S1–S3 on that side. Unwinding at a wall is the breakout cue.
- **UI**: two lists (desktop: side by side in the side column; phone: segmented). Each line reads `26500 CE  +1.2L (+18%)  LTP −4.3  SB · capping  [wall R1]`.

### 5.8 Multi-expiry (`O.cumulativeOi(chains) → { rows, perExpiry }`)
- **Selected expiries**: the toolbar expiry plus up to 3 more from `/v1/expiries`. The default extras are none; the user picks them.
- Each extra chain is fetched with `strikes=40` every 30 s (not every 3 s) and on selection change.
- `rows`: union of strikes. For each strike and side: `oi = Σ OI` in **lots** (each chain's own lot size, so lot changes do not distort the sum), `d = Σ d` (prev-close only), and `by: { [expiry]: oi }`.
- `perExpiry`: for each expiry: PCR_OI, max pain (with edge), R1, S1, total CE and PE OI in lots, DTE, lot size.
- **UI**:
  - Per-expiry table (phone: cards) with columns Expiry, DTE, Lot, CE OI, PE OI, PCR, Max pain, Support, Resistance, plus an "Include" checkbox per row.
  - A ladder Scope switch, "This expiry | Combined (n)", appears when n ≥ 2. In Combined, the ladder, walls and PCR use `rows` (lots only; the Unit control is disabled with the title "Combined OI is in lots: lot sizes differ by expiry"). The window is forced to Prev close (snapshots are per expiry).
  - Note under the table: "Monthly expiries carry positional and hedge OI; rollovers distort ΔOI in the final days."
- BANKNIFTY has monthlies only. The list comes from `/v1/expiries`, so nothing assumes weeklies.

### 5.9 Verdict line (`O.oiVerdict({ walls, pcr, buildup, spot, move, maxPain, relevance }) → string`)
The template joins only the parts that are non-null:
`"Range {S1}–{R1} · {buildup.text} · PCR {pcr} {band word} · Max pain {mp} ({relevance})"`.
- Example: "Range 25900–26500 · Writers on both sides · PCR 1.08 balanced · Max pain 26300 (low relevance)".
- The line ends with "Context, not advice." in quiet text.
- `aria-live="polite"` announces the line only when its text changes, and at most once a minute.

### 5.10 Pin zone (arbitrageur; shown in the Walls block footer)
`pinShare = Σ (CE OI + PE OI) at the 3 strikes nearest spot ÷ chain total OI`. It is shown as "Pin zone 26350–26450: 14% of OI" when ≤ 2 sessions remain, and hidden otherwise.

## 6. The OI ladder (`oi.js`, `createLadder`)

### 6.1 Structure
- A real `<table class="oi-ladder">` with the `<caption>` "Open interest by strike, {window label}, {unit}" (visually hidden).
- Header: `CE Δ | Calls OI | Strike | Puts OI | PE Δ`.
- One `<tr>` per fetched strike.
- The band is applied by toggling `tr.hidden`, never by rebuilding.
- Build key: `underlying|expiry|scope|allStrikes|metric|unit`. Anything else is patched.

### 6.2 Cells
- **Bar cells**: a fixed track `<span class="trk">` holds two children:
  - `.ghost`: OI at the reference, `transform: scaleX(OIr/max)`.
  - `.now`: the metric value, `scaleX(v/max)`.
  - Calls grow from the strike side toward the left (`transform-origin: right`); puts grow toward the right.
  - The value text sits in `<span class="v">` at the outer edge.
  - `max` = largest value in the visible band across both sides. Rescaling only happens when `max` changes by more than 10%, to stop jitter.
- **Metric** (segmented control: OI | ΔOI | Volume):
  - OI: `.now` = OI now, ghost = OIr. The added part is the solid overshoot past the ghost; unwinding shows as a striped ghost beyond `.now`.
  - ΔOI: `.now` = |d|. `+` and `−` are shown in the Δ column and `.now` gets the class `neg` (striped) when d < 0. No ghost.
  - Volume: `.now` = V, no ghost.
- **Δ cells**: signed compact d, with `dPct` in a smaller second line on desktop only. Next comes the build-up chip: 2-letter text (LB/SB/SC/LU/CH) whose title gives the full name and its direction for that side.
- **Strike cell**: the strike, plus tags in this order of priority: `MP` (max pain), `R1–R3` / `S1–S3`, `±1σ` edges (`emUp`/`emDown`), and a held-position badge (`+2L` / `−3L`, using `heldLots`, which respects `cfg.positions`). On phone, at most 2 tags show and the rest go into the detail row.

### 6.3 Visual
- Both sides use the same ink: `.now` is `hsl(var(--foreground) / 0.34)`, `.ghost` is `/ 0.12`, and a striped unwinding part uses `repeating-linear-gradient` at `/ 0.22`. Wall rows (rank 1) use `/ 0.5`.
- No red or green anywhere in the ladder.
- **ATM row**: background `hsl(var(--ios-blue) / 0.06)`.
- **Spot line**: a 1 px `--ios-blue` rule (an inset box-shadow) on the boundary between the two strikes that bracket spot, with a right-aligned label "Spot 26400.50" in the strike column of the row below.
- **±1σ band**: rows inside the band get a 2 px inset left rule `hsl(var(--ios-blue) / 0.25)` on the strike cell.
- Dark mode works through tokens only.

### 6.4 Scroll
On the first build and on a scope or underlying change, scroll the wrapper so the ATM row is centred. Afterwards, never move the scroll: patching keeps `scrollTop`. A "Back to ATM" text button appears in the panel head when the ATM row is out of view.

## 7. Snapshots and windows (`oi-store.js`)

### 7.1 Recording
- `recorder.offer(chain, nowMs)` is called after every successful chain load for the main expiry, and for each extra expiry on its 30 s load.
- A snapshot is written when:
  - the session is open (`O.marketSession(now).phase === "open"`, IST Mon–Fri 09:15–15:30), or `app.state.demo` is set;
  - **and** at least 60 s have passed since the last snapshot for that key;
  - **and** `freshness.asOf` differs from the last snapshot's.
- Key: `${underlying}|${expiry}|${istDate}`.
- Snapshot shape (columnar, compact): `{ t, spot, lot, k: number[], co: number[], po: number[], cl: number[], pl: number[], cv: number[], pv: number[] }`. Arrays are aligned to `k`; missing values are stored as `null`. The `cv`/`pv` fields hold cumulative day volume, so window volume = `V_now − V_ref` (clamped at ≥ 0).
- Storage: IndexedDB database `mcb-oi` v1, object store `snaps`, keyPath `["key","t"]`, index `key`.
  - Cap: 400 per key. When over the cap, the oldest are dropped.
  - On open, delete snapshots whose `istDate` is more than 3 IST days old.
  - Every call is wrapped in try/catch. On failure the store falls back to memory only, and the Window tile title says "Not saved: browser storage unavailable".
- Writes are async and never block the draw. Expected size: 201 strikes × 6 arrays ≈ 8 KB JSON per snapshot, so a full day is about 3 MB per key, which is fine for IndexedDB.
- Interface: `openStore({ backend })`, which returns `{ offer, list(key) → snaps (sorted), latest(key), clearKey(key) }`. `backend` is either `indexedDbBackend()` or `memoryBackend()`. The memory backend is what Node tests use.
- Playwright seeds snapshots by importing `/dashboard/oi-store.js` in `page.evaluate` and calling `put`.

### 7.2 Windows
Choices: `Prev close | 5m | 15m | 30m | 1h | Since open`. The default is `Prev close`, or `Since open` when the chain has no `oiChange` (O8).

`O.pickRef(snaps, nowMs, win) → { snap, label, ok, reason }`:
- For a minute window W: `snap` = the latest snapshot with `t ≤ now − W`. When none exists:
  - If the earliest snapshot is still at least `W/2` old, use it: `ok: true`, with the label "since 10:42 (22m)".
  - Otherwise return `ok: false` with the reason "Recording since 10:42 · 15m ready at 10:57".
- Since open: the first snapshot of the IST day. If it was taken later than 09:20, the label reads "since 10:42 (opened late)".
- Prev close: no snapshot. `ok` is `chain has any non-null oiChange`.
- A window that is not ok is disabled in the selector (an `<option disabled>` or a chip with `aria-disabled`), with the reason in its title. If the chosen window becomes unavailable (underlying or expiry change), fall back to Prev close, or to Since open, or to the first window that is ok, and say so with a toast.

`O.oiWindowRows(chain, refSnap | null) → rows [{ strike, ce: { oi, oiRef, d, dPct, ltp, ltpRef, dLtp, v }, pe }]` is the single input to everything in §5. With `null` it uses the prev-close fields.

### 7.3 Coverage text (Window tile and timeline)
- "Recording since 10:42 · 37 snapshots · every 1 min"
- "Market closed · showing the last session" (not open and not demo)
- "Demo data: snapshots recorded off-hours"

### 7.4 Series for the chart engine
`O.oiSeries(snaps) → [{ t, spot, ceOi, peOi, pcr, maxPain, r1, s1 }]` (totals in lots). The timeline panel shows:
1. A placeholder box with the `card` title "OI over time" and a centred label "Chart engine slot · Call OI, Put OI, PCR, max pain and spot vs time ({n} points ready)". It is `role="img"` and its `aria-label` says the same.
2. A wall-migration line computed from the series: "Call wall: 26400 (09:31) → 26500 (11:02) · Put wall: 26000 since 09:31".

The prepared series is exposed as `oiPage.series()` so the engine can be plugged in later without more maths.

## 11. Accessibility
- The ladder is a semantic table with `<th scope="col">`, and the strike cell is a `<th scope="row">`. Bars are `aria-hidden` and every value is in text.

- Colour is never the only signal: Δ has a sign, build-up has letters and a title, walls have tags, the spot line has a label, and unwinding is striped as well as signed.
- Tiles: `role="group"` with `aria-label`. Each tile's `title` holds the formula. The "?" sheet is the long-form text.
- `prefers-reduced-motion`: no transitions on the bar `transform`.
- Contrast: text tokens meet WCAG AA in both themes. Check `.ghost` against the background only as decoration.

## 13. Performance
- Per tick:
  1. `oiWindowRows` (O(n) with a strike → index map for the reference).
  2. `pcrSet`, `oiWalls` ×2, `buildupSummary`, `oiMovers`: all O(n).
  3. `maxPainCurve` O(n²) with n ≤ 201 (about 40k multiply-adds, under 1 ms).
  4. Ladder patch: only cells whose signature changed, with bars as `transform` writes.
- The side blocks and tiles re-render only when their signature string changes.
- Budget: ≤ 10 ms main thread per tick on desktop (measure as `st.patchMs`, printed in the clock title).
- Snapshot write ≤ 1 per minute per key, async. List reads are cached in memory after the first load per key.
- No timers beyond the existing `every(REFRESH_MS)` and one 30 s extra-expiry cadence, which is folded into the same timer by counting ticks.
